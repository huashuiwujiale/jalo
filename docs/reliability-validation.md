## 真实模型专项

明确使用已配置的 **qwen/qwen3-1.7b**，上下文 16384，最大输出 4096，专项脚本上限 8 步。没有切换模型、云端兜底或执行模型提出的终端命令。所有修改仅发生在新建临时样例中。

- **文本修改成功**：先真实读取 `sample.txt`，调用编辑工具将 `hello` 改为 `hello Jalo`；核对磁盘内容一致。TXT 明确标记未进行语法检查。
- **Vue 业务任务失败，保护生效**：请求删除多行“新增”按钮并保留“导出”。模型连续产生重复属性、缺失结束标签等无效候选，三次检查失败后停止；文件未改变，实际修改列表为空。不能将此案例计为模型完成了任务。
- 结构化探测通过只证明返回过有效工具调用，不等于具备可靠编辑或总结能力。

可复现脚本：`scripts/reliability-live.ts`。原始结果摘要：[reliability-live-report.json](reliability-live-report.json)。该 JSON 保留当次真实返回，之后补充的语法诊断行号不回填旧报告。

## 真实桌面操作

通过 Electron 界面在临时验收项目完成：

1. 搜索文件、带行号预览、添加引用；切换项目后文字保留，旧引用失效且不能提交。
2. 提交计划轮次。真实模型尝试调用未提供的 `replace_lines`，工具入口拒绝，文件未变。
3. 按计划执行创建新的关联轮次。验收中发现模型沿用旧“只读”错误语境：已调整为新的执行上下文，保留原始目标、计划关联和存储历史，要求重新读取。修正后真实工具最终写入 `hello Jalo`。
4. 模型最后的文字总结仍有错误，但主进程记录与右侧差异正确显示真实写入；总结没有覆盖真实结果。
5. 退出、重新启动开发版，历史轮次及差异仍在。
6. 点击“预览回退此文件”，反向差异为 `hello Jalo → hello`；确认后文件恢复，轮次状态为 `reverted`，任务总差异清空，恢复副本保留修改后内容，模型上下文增加重新读取提示。

保留临时验收项目供人工复查；没有通过验收任务修改业务仓库。

## 实现与边界

- 写入前检查点在 SQLite 中持久化并确认；写入后的版本经文件工具重读核对后进入已写入记录。进程在确认中途退出时，未核验检查点显示待人工检查，不推断写入成功、不自动重放、不开放回退。
- Vue 根据最近的项目依赖判断 2/3，使用应用自带解析器。不会加载项目 ESLint/构建配置，也不做类型检查、样式验证或业务验收。特殊预处理语言、外部块与未知版本明确标记未完整检查；复杂语法方言可能需要人工处理。
- 回退是逐轮次、逐文件的内容版本检查；没有整项目或逐代码块回退。文件被后续轮次或外部修改后，拒绝覆盖。若任务已记录的文件又有手工改动，需新建任务继续，避免混入旧任务总差异。
- 旧历史没有补造执行证据，不能安全证明的旧修改不提供回退。
- 终端仍是用户权限下的命令执行，不是内核沙箱。直接文件工具的路径检查不宣称能抵御同一用户恶意并发替换整个目录的攻击。
- 当前使用的 1.7B 模型能力有限。软件可以约束权限、拦截部分错误并如实记录结果，不能保证模型总能完成需求。

解析接口依据：[Babel parser](https://babeljs.io/docs/babel-parser)、[Vue SFC parser](https://github.com/vuejs/core/blob/main/packages/compiler-sfc/README.md)、[vue-eslint-parser](https://github.com/vuejs/vue-eslint-parser)。本实现只使用解析入口，不调用编译或代码生成入口。
