# Jalo

**Your models. Your code.**

自己的模型，自己的代码。

Jalo 是佳乐（Jiale）发起的本地编程助手，名字取自「佳乐」的音感，也呼应 Local。

Jalo 是一个面向 macOS 的本地编程助手。它连接 LM Studio 中运行的模型，让模型在你选择的项目里读取代码、生成修改，并在每次终端命令执行前征求确认。

> 当前支持开发运行及本机生成的 macOS ARM64 DMG。安装包使用本地临时签名，未做 Apple Developer ID 签名或公证，尚未提供面向公众的正式发行包。模型能力会直接影响任务完成质量；Jalo 负责限制权限、验证写入并如实记录结果，不保证每个本地模型都能完成复杂改动。

## 安装版：安装、更新与排查

### 安装到自己的 Mac

现有打包配置面向 **Apple Silicon（ARM64）Mac**。在本机生成的安装包位于 `release/Jalo-<版本>-mac-arm64.dmg`；这里的配置不代表 GitHub 上已经发布可下载的安装包。

1. 退出正在运行的 Jalo 开发版或安装版。
2. 打开 DMG，把 **Jalo** 拖入 **Applications（应用程序）**。
3. 推出安装镜像，从“应用程序”启动 Jalo。
4. 在 LM Studio 启动本地服务器，然后按下方步骤连接模型。

安装版包含界面、任务引擎与运行时，不需要另行运行 Node.js 或 Vite；模型推理仍由 LM Studio 提供。

### 替换安装包

1. 先完成或停止所有运行中、等待确认及排队任务。
2. 在 **模型与设置 → 应用与诊断 → 打开数据目录** 中找到实际存储位置。退出 Jalo 后复制整个数据目录作为备份，备份应包含数据库、`backups/` 与 `recovery/`。
3. 打开新 DMG，将 Jalo 拖进 Applications 并选择替换；从 Applications 重新打开。
4. 在设置中核对版本、项目和任务记录。替换应用不会清空数据目录；从旧版 Local Code 升级时继续使用原数据目录。

当前没有自动更新。每次发版应先更新 `package.json` 和 lockfile 的版本号再打包；应用内版本来自正在运行的应用元数据，开发版与安装版会明确区分。需要回到旧版本时，退出应用并恢复与该旧版本匹配的完整数据备份，避免直接用旧程序写入升级后的数据库。

需要自己生成安装包时，在开发依赖准备好后手动执行（此命令会编译和打包）：

```sh
npm run dist:mac
```

产物保留在 `release/`，不会自动上传。源码更新不会自动更新已经安装的应用。

### 查看信息与导出诊断

- **模型与设置 → 应用与诊断** 显示当前应用版本、开发/安装模式、架构、运行时版本，以及实际数据和日志目录；系统菜单 **Jalo → 关于 Jalo** 使用同一版本来源。
- **打开数据目录** 只打开 Jalo 实际使用的目录；旧安装可能位于 `~/Library/Application Support/Local Code/`，新安装通常是 `~/Library/Application Support/Jalo/`。
- **导出诊断日志** 打开本地保存对话框，导出 JSON 文件；任务运行期间也可使用。文件只含运行环境、最近 50 个任务的状态/数量统计，以及最多 1000 条结构化事件。错误正文转为错误类别，不包含访问令牌、服务地址、项目名称/路径、模型名称、聊天、源码或终端命令与输出，不会自动上传。
- 结构化日志保存在实际数据目录的 `logs/diagnostics.jsonl`，单文件上限 512 KiB，轮转保留上一份 `diagnostics.1.jsonl`，最多两份。日志写入失败不会打断任务，设置页会提示；导出会标明日志读取不完整或条目被截取。
- 启动失败导致无法打开设置时，可以通过 Finder 的“前往文件夹”进入上述实际数据目录，查看 `logs/`。旧版没有记录的事件不能在升级后补造；详细原始错误仍需在任务对话里查看。

## 启动

需要 **Node.js 22.14+**、npm，以及提供 `/api/v1/models` 的 LM Studio 版本。

```sh
git clone https://github.com/huashuiwujiale/jalo.git
cd jalo
nvm use 22
npm ci
npm run dev
```

首次安装依赖后，也可双击 `启动.command`；脚本会优先使用可用的 Node 22 环境。目录已有 `node_modules` 时不会重复安装。

如果项目已有 `node_modules`，可直接 `npm run dev`。启动脚本会启动本地 Vite 服务及 Electron 窗口；没有编译、打包步骤。开发服务使用 `127.0.0.1:5173`，端口被占用时明确报错。

1. 在 LM Studio 中下载支持工具调用的模型，启动 Developer 页的本地服务器。
2. 打开“模型与设置”，填写地址（默认 `http://127.0.0.1:1234`）及可选令牌，保存并检测连接。
3. 选择默认模型并保存。可手动加载/卸载；开始任务时也会加载尚未加载的模型。
4. 添加项目文件夹，输入要求，点击发送或按 `⌘ Enter`。
5. 每条终端命令都展示完整内容、工作目录和超时时间。选择允许或拒绝。
6. 右侧查看文件差异或终端输出。任务结束后可补充要求；新建任务可进入队列。

## 核心能力

- 中文三栏界面：项目和历史任务、对话与执行过程、文件差异和终端输出。
- LM Studio 原生 v1 模型管理，OpenAI 兼容 Chat Completions 流式推理。
- 任务开始时真实检测结构化工具调用，不把普通聊天文本当作可执行命令。
- 独立 utilityProcess 任务进程；单任务运行、FIFO 排队，模型与配置在队列期间锁定。
- 目录浏览、文本/文件名搜索、分页读取、创建/替换文件、精确文本补丁、命令确认及差异展示。
- 自动读取根目录及目标文件父目录中的 `AGENTS.md`。遇到新的目录指令，先交给模型再允许写入。
- 保存文件原文备份，修改前检查是否被外部修改。取消时终止命令进程组；重启后中断任务不会自行恢复执行。
- 保留用户要求和最近完整工具调用组，压缩较早记录以控制上下文大小。

## 0.2：引用、计划、审查与安全回退

- 输入框点击 **@ 引用文件**，或输入 `@`，搜索当前项目的真实文件。只读预览支持分页和行范围；点击一行选择，Shift 点击扩展范围。提交时重新读取并核对版本。切换项目保留草稿，旧项目引用会标为失效。
- **执行**默认允许项目内文件写入，终端命令始终逐条确认。**计划**只读分析并给出步骤；完成后点击 **按计划执行**启动关联的新轮次，重新读取文件。**审查**针对右侧选定轮次的实际差异，只提出问题。只读限制同时应用于工具列表和执行入口。
- 修改先生成候选内容，核对原文件版本，进行本地语法解析，保存 SQLite 检查点与原文备份，再写入并重读核对。Vue 模板结构/表达式和 JS/TS 脚本、JS、TS、JSON 使用应用自带解析器；不执行项目脚本、配置或编译。Vue 从最近的 package.json 识别 2/3 主版本。
- 原文件已有语法错误时暂停该文件自动写入；新候选语法失败不写盘。同一文件连续三次编辑定位或语法检查失败停止本轮。未知语言、未知 Vue 版本、外部块或预处理模板明确标记未完整检查。样式、类型、依赖是否存在和业务行为不属于语法解析保证。
- 每次提交保存独立轮次。右侧可切换 **本轮修改 / 整个任务修改**及历史轮次；结果以实际写入记录为准。显示 **修改已写入，待验收**，模型总结不能替代该状态。
- 选择轮次和文件后点击 **预览回退此文件 → 确认回退**。当前内容必须仍等于该轮写入后的内容；有后续轮次或外部修改时拒绝覆盖。项目有运行/排队任务时不允许回退。成功回退会更新差异并提醒模型重新读取。
- 回退前保存可恢复副本和操作日志：`<userData>/recovery/<run-id>/*.json`。新建文件也先保留副本再移除，不使用 Git 强制重置。
- 升级前生成数据库 `local-code.sqlite.before-v2-<时间戳>.bak`，保留原数据目录和历史。SQLite 新增 `runs`、`checkpoints` 表；旧记录显示“历史数据，缺少轮次核验”。崩溃时未完成确认的检查点不宣称写入成功，也不开放回退。

文件引用限制：最多 8 个，单个范围最多 400 行，总内容最多 12000 字符；预览每页最多 100 行/16000 字符，并明确提示后续内容。文件选择器搜索最多扫描 10000 项、返回 80 条，达到限制时要求缩小范围。

### 验证可靠性

在 **模型与设置 → 模型能力实测** 点击 **保存配置并实测**，使用当前选择的模型和生成参数。先在模型列表中加载模型；实测不会自动加载、卸载或切换模型。

- 三项独立临时样例：读取随机校验码、修改文本并保留其他文件、删除 Vue 2 多行“新增”按钮并保留“导出”和脚本。
- 使用同一任务引擎和文件工具；终端命令在工具列表和执行入口均禁用。实际文件、写入记录、修改后的重新读取及 Vue 语法共同决定结果，模型自报完成不算通过。
- 每项最多 8 步（设置更小时沿用设置）、3 分钟。上下文取设置与已加载实例容量中的较小值，报告显示实际参数、模型实例、应用版本、检查项和耗时。
- 实测与正常任务互斥，可停止；关闭设置不会停止实测。应用退出后未完成报告标为中断，不自动重跑。临时样例在正常结束或停止后清理。
- 最近 10 次报告存入现有 SQLite 的 `evaluations` 表，重启后仍可查看。从数据库 v2 升级时先生成 `local-code.sqlite.before-v3-<时间戳>.bak`，再增加报告表，保留项目和任务。报告不保存访问令牌、聊天全文或项目源码。
- 样例通过率只表示这三项测试的结果；全部通过不保证能完成任意业务任务。服务或模型未准备好、取消、中断时不展示完成的通过率。

```sh
node --import tsx --test tests/*.test.ts
# 在 LM Studio 中加载指定模型后，仅使用临时样例：
JALO_MODEL=qwen/qwen3-1.7b node --import tsx scripts/reliability-live.ts
```

该专项脚本不自动加载/切换模型，拒绝全部终端命令，在临时目录生成文本与 Vue 样例，按实际文件内容记录成功或失败。通过工具调用探测不代表能完成业务任务。验收细节见 [可靠性验收记录](docs/reliability-validation.md)。

## 数据与权限

### 项目与任务管理

- 左侧任务记录支持重命名，按标题或用户要求搜索；搜索范围是当前项目、当前或已归档分类。
- 点击任务旁的归档按钮可收起已结束的任务；在“已归档”中仍可查看记录，恢复后可继续对话。运行中、等待确认或排队的任务需先停止或结束。
- 点击项目旁的移除按钮并确认后，只隐藏项目入口，不删除代码、任务记录或备份。重新添加同一目录可恢复原项目及历史任务；项目有未结束任务时禁止移除。
- 以上状态保存在本地数据库中，重启后保留。归档及移除不是磁盘空间清理。

### 存储位置与保护

- SQLite 数据库位于 Electron `userData` 目录下的 `local-code.sqlite`，新安装使用 `~/Library/Application Support/Jalo/`。已有 Local Code 版本的数据会继续使用原来的 `~/Library/Application Support/Local Code/`，同时保留原系统加密身份，以兼容任务记录和令牌。
- 原文备份位于同目录的 `backups/<task-id>/<文件路径哈希>.json`，保存相对路径及首次修改前内容；新建文件的原文为 `null`。0.2 新轮次可在右侧预览反向差异后逐文件安全回退；历史未核验记录不开放回退。
- 访问令牌用 Electron `safeStorage` 加密后入库；不可用时拒绝保存令牌。
- 数据库保存任务上下文、工具日志和文件原文，请按本地源代码数据妥善管理。当前开发版不会自动清理历史数据。
- 界面进程启用 sandbox、contextIsolation，禁用 Node 集成；只暴露固定 IPC 方法，不开放任意命令或文件系统接口。
- **终端命令不是系统沙箱**，经确认后以当前用户身份执行，可能影响项目外资源。命令不会继承配置中的 LM Studio 访问令牌。
- 直接文件工具限制在所选项目内，拒绝符号链接、路径越界和 `.git` 内部访问，写入硬链接文件也会被拒绝。这些应用层检查不等同于对抗同一用户恶意并发文件替换的内核沙箱。
- 文件差异仅追踪本任务通过文件工具产生的修改，不包含原有 Git 改动或终端造成的文件修改。若本任务已改过的文件又被外部修改，会要求在新任务中继续，避免混入他人的差异。
- 默认只连接本机。若自行修改服务地址，项目上下文会发送到该地址；不会自动回退到任何云端模型。
- Git 仓库不会保存任务数据库、访问令牌、文件备份或恢复副本；这些本地数据已由 `.gitignore` 排除。

## 参数与限制

- 默认上下文 16384、最大输出 2048、温度 0.2、最多 30 步、命令超时 60 秒。
- 已加载模型沿用实际上下文，任务使用设置与实际容量中的较小值。要扩大实例上下文，先卸载再加载。
- 对推理/加载设置 5 分钟请求上限；命令确认等待用户操作，可通过停止任务退出。
- 文本文件上限 256 KB，单次写入内容上限 48000 字符；读取输出 24000 字符，命令输出 32000 字符；大项目搜索最多扫描 3000 项、返回 50 条匹配。
- 上下文采用保守的字节估算，并非对应模型的精确 tokenizer；服务仍可能因容量不足拒绝请求，界面会显示原因。
- 不包含训练、下载模型、内置推理、浏览器操作、插件、多智能体、自动更新或 Apple 公证分发。

## 测试

```sh
npm test
npm run test:live
```

单元测试使用模拟模型和临时文件，覆盖流式分片、工具调用探测、取消/拒绝、超时、路径越界、符号链接、硬链接、文件冲突、目录指令、上下文压缩和 SQLite 重启恢复。

真实模型测试只创建临时加法样例，读取并修复后请求执行 `node --version`，终端输入 `yes` 才执行。模型通过 `LM_STUDIO_MODEL` 指定；地址与令牌可用 `LM_STUDIO_URL` 和 `LM_STUDIO_TOKEN` 环境变量传入。测试加载的模型在结束时卸载，原先已加载的实例保留。

自动化验收可显式使用 `npm run test:live -- --approve-fixture-command`，仅允许临时样例目录内的固定只读命令 `node --version`，其他命令一律拒绝。该开关只属于测试脚本，桌面应用没有自动批准模式。

## 代码结构

| 目录 | 职责 |
| --- | --- |
| `src/` | React 页面、布局和交互 |
| `electron/` | 窗口、受限 IPC、队列、SQLite、预加载桥接 |
| `engine/` | 模型适配、任务循环、文件/命令工具、上下文压缩 |
| `shared/` | 接口类型及输入校验 |
| `tests/` | 可重复逻辑测试 |
| `scripts/` | 开发启动及真实模型验收 |

SQLite 使用 `sql.js`，避免开发版 Electron 原生模块重编译；单写入者在主进程中将数据库原子保存到磁盘。后续数据量增长时可迁移到原生 SQLite/WAL，当前不面向多进程并发写库。

接口依据：[LM Studio 模型管理](https://lmstudio.ai/docs/developer/rest)、[工具调用](https://lmstudio.ai/docs/developer/openai-compat/tools)、[Electron utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)。
